## Lens 1 — Architectural drift (2 findings)

The soundness-critical surface is **clean**: no agent-layer mutation of the
graph/reachability/findings (the advisory tiers only read via `get_node`/`edges`);
network I/O is confined to `correlate/osv.py`, `correlate/enrich.py`,
`agent/client.py`; `reachability.py` and `correlate/report.py` import no I/O; all
four analyzers gate `calls`/`route_to_handler` edges on resolution and record
`unresolved_*` otherwise; the reachability BFS skips dangling edge targets.

### A1 · MEDIUM · `scanner/correlate/report.py:152`
```python
payload["verdict"] = verdicts.get(finding.dependency_id) or (
    "reachable" if finding.reachable else "unreachable"
)
```
The three-way verdict is meant to come only from `reachability.repo.verdict_by_dep`,
whose four-part "fully resolved" rule is the **only** sound source of the
confident `unreachable` label. Here the serialization layer invents a fallback:
if a dep id is missing from `verdict_by_dep`, a non-reachable finding is defaulted
straight to `unreachable` — bypassing the `reachable_region_fully_resolved` gate.
**Consequence:** if the fallback ever fires, the JSON/`--bundle` payload shows
`unreachable` (safe) for a dependency reachability.py would never clear — the exact
cardinal false-safe failure mode. The sibling text path (`_reach_text`) correctly
returns neutral wording when the verdict is unknown, so the two outputs disagree.
Trigger is an edge case (verdict_by_dep is built over all declared dep ids), which
keeps it out of HIGH. **Fix:** default the missing-key case to
`potentially_reachable` (or raise); never re-derive the verdict from
`finding.reachable` in the transport layer.

### A2 · LOW · `scanner/agent/__init__.py:1`
```python
"""Agent layer: advisory, LLM-assisted exposure assessment of reachable findings.
... The layer performs no network I/O except through LLMClient ..."""
__all__ = ["Assessment", "assess_findings", "LLMClient",
           "Triage", "triage_findings", "Usage", "investigate_usage"]
```
The package docstring describes a single tier and claims no I/O beyond LLMClient,
but the package now exports three tiers (assess/triage/usage), and `usage.py`
additionally re-walks the repo filesystem via `walk_repo`. **Consequence:** a
developer reading the entry point is told two of three capabilities don't exist and
the stated I/O contract is wrong. Part of a broader stale-docs theme (see Lens 5).
**Fix:** update the docstring to cover all three tiers + the usage filesystem walk.

## Lens 2 — Test value (4 findings)

The suite is **strong** on the cardinal rule: analyzer/cross-file tests pair
resolved-edge-present with false-edge-absent, `test_golden_fixture.py` uses exact-
match sets plus `test_no_forbidden_edges`, and the three LLM-tier tests exercise
the **real** offline heuristics (mocking only the client). The gaps are in the
network-correlation core and CLI wiring.

### T1 · HIGH · `scanner/correlate/enrich.py:189` (+ `fetch_nvd_cvss`, `_apply_nvd`, `_epss_chunks`, `_to_float`)
```python
metrics = (vulns[0].get("cve", {}) or {}).get("metrics", {}) or {}
for key in ("cvssMetricV40", "cvssMetricV31", "cvssMetricV30", "cvssMetricV2"):
    ...
    severity = data.get("baseSeverity") or chosen.get("baseSeverity")
```
The CVE-correlation layer is the product's core, yet its NVD/EPSS JSON parsing has
**zero** direct tests — `test_correlate.py` mocks the whole boundary
(`monkeypatch.setattr(enrich, "fetch_kev_catalog", ...)`, `query_epss`), so the real
response-parsing never runs (grep: `_parse_nvd`/`fetch_nvd_cvss`/`_apply_nvd`/
`_epss_chunks` appear nowhere in tests/). **Consequence:** a wrong JSON path (NVD
renaming a field, a V2-vs-V3 severity nesting slip, an EPSS-chunk off-by-one)
silently yields absent/wrong CVSS → wrong severity → wrong `rank_findings` order,
and nothing fails. **Fix:** feed canned NVD/EPSS/KEV JSON blobs directly to the
parse functions (stub only `_get`/`urlopen`), asserting exact score/vector/severity,
version-precedence, and Primary-first selection.

### T2 · MEDIUM · `scanner/correlate/cache.py:70`
```python
if isinstance(expires, (int, float)) and expires < time.time():
```
Only the fail-soft path is tested (`test_correlate.py:481` points the cache at an
uncreatable dir, so every `get` is a miss by construction). No test stores a value
and reads it back, and the TTL-expiry branch above is untested. OSV vuln records now
cache with a 7-day TTL. **Consequence:** inverting the comparison, or a set/get key
mismatch, would serve expired CVE data indefinitely (or never cache) and the suite
stays green. **Fix:** add a happy-path round-trip test (isolated tmp cache dir) and
an expiry test with a past TTL asserting a miss and that the stale file is unlinked.

### T3 · MEDIUM · `tests/test_triage.py:376`, `tests/test_usage.py:334`
```python
assert "triage" in bundle and isinstance(bundle["triage"], list)
assert "usage" in bundle and isinstance(bundle["usage"], list)
```
These CLI-wiring tests accept an **empty** list. The fixture is `vulnerable-app`,
where PyYAML is reachable with a CVE, so both tiers *should* emit non-empty content.
**Consequence:** if the CLI regresses to never invoking triage/usage (wired to `[]`,
exception swallowed, flag mis-parsed), these tests still pass — the end-to-end wiring
of two of the three advisory tiers is effectively unverified. (The parallel `assess`
test at `test_agent.py:647` *does* assert non-empty + field contents — mirror it.)
**Fix:** assert non-empty and spot-check one entry's key/verdict.

### T4 · LOW · `tests/test_triage.py:349`
```python
assert result
```
Truthiness-only precondition. Inert — it guards an otherwise strong per-item loop
and the tier's content is pinned by the offline-heuristic tests above it. Noted for
completeness; no bug slips through.

## Lens 3 — Over-abstraction & duplication (4 findings)

No single-implementation over-abstraction found — the manifest/analyzer registries
each have four genuine impls. The findings are all duplication in the agent tiers
and the tree-sitter analyzers.

### O1 · MEDIUM · `agent/triage.py:555`, `agent/usage.py:670`, `agent/assess.py:967`
The entire "configure client → run LLM in a bounded pool → per-item fall back
offline → sort" harness is duplicated at three sites, including the load-bearing
error guardrail:
```python
with ThreadPoolExecutor(max_workers=min(8, len(prepared))) as executor:
    llm_results = list(executor.map(_call, prepared))   # _call swallows Exception -> None
```
**Consequence:** the copies already diverge — `usage.py` guards with `if use_llm:`
while the other two use `if use_llm and prepared:`. The pool size / exception→offline
fallback / ordering guarantee is the layer's core safety property; hardening one copy
(new error class, different worker bound) silently skips the other two, exactly where
drift is most dangerous. **Fix:** extract one `_run_tier(prepared, *, use_llm, llm_fn,
offline_fn, sort_key)` into a shared agent module.

### O2 · MEDIUM · `agent/triage.py:146`+`assess.py:224`; `triage.py:151`+`usage.py:172`
`_reachable_dep_ids` (triage == assess) and `_called_symbols` (triage == usage) are
byte-identical, pure graph reads with no tier logic:
```python
def _reachable_dep_ids(reachability):
    return {dep["id"] for dep in reachability.repo.reachable_deps}
```
**Consequence:** the `calls edge → dst dep → attrs['symbol']` shape is the contract
between edge-emission and every tier's consumption; if that schema changes, 2–3 hand
edits are needed and an omission silently yields empty symbol sets → wrong "no static
usage" classifications. **Fix:** move both to a shared `scanner/agent/_graph.py`.

### O3 · MEDIUM · `javascript_analyzer.py:151/173`, `go_analyzer.py:122/139`, `php_analyzer.py:111/128`
`_leading_doc_comment` and `_node_signature` are byte-for-byte identical across the
three tree-sitter analyzers — generic node ops (`prev_sibling`, `start_point`,
`child_by_field_name("parameters")`) with no language-specific content. **Consequence:**
any fix to doc-comment extraction or signature truncation must be applied three times;
a miss means one language silently diverges in the doc graph. **Fix:** a shared
`scanner/analyzers/_treesitter.py`. (Do *not* fold in `_clean_comment` — its comment-
marker sets genuinely differ per language; that trio is deliberate.)

### O4 · LOW · `agent/triage.py:441`, `agent/usage.py:571` vs `agent/assess.py:387`
`_normalize_confidence` is duplicated in triage+usage, while `assess.py` already has
the general form `_normalize(value, allowed)` that trivially subsumes it (and
`usage._normalize_usage_kind`). Inert today. **Fix:** lift the parameterized
`_normalize(value, allowed, *, default)` into the shared module, or declare the
mirroring deliberate.

## Cross-cutting themes

1. **Stale docs from this session's features** (C1, C2, C5, A2): method resolution, the
   usage tier, and JS/Go cross-file all landed without a README/docstring pass. Highest
   user-facing risk because it understates soundness/recall — the project's core claim.
   *Do a documentation pass before anyone reads the repo.*
2. **Three-way verdict not fully propagated to consumers** (A1 + D1): the sound verdict
   is computed but (a) can be overwritten by an unsound fallback in the JSON layer and
   (b) isn't surfaced in the dashboard. Fixing both tightens the one guarantee the tool
   makes.
3. **Agent-tier duplication** (O1, O2, O4): three siblings grew by copy-paste; the shared
   safety harness and graph-read contract should live in one module before the next change.
4. **Network-correlation core is under-tested** (T1, T2): the one layer that does real I/O
   ships its parsing and caching unverified.

## What's healthy (not everything needs fixing)

- The cardinal rule (no false edges) is enforced in code *and* in tests across all four
  analyzers, with paired positive/negative assertions and an exact-match golden fixture.
- Clean layering: advisory tiers never mutate deterministic output; I/O is quarantined.
- No dead first-party exports; no single-impl over-abstraction; no dead dependencies.

No numeric score is assigned (a score gets tracked instead of fixed). This is the first
audit in this directory, so there is no prior report to diff against.
